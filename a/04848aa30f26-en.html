Your Computer Memory is Far More Complex Than You Think

The simple memory model as an addressable byte array is an extreme simplification of modern mechanisms.

The classic memory model as an addressable byte array is a simplified, even misleading, view of modern systems. In reality, the address you use is often not a physical location in RAM, and the data read can come from caches, disks, or even other memory levels.

A hierarchy of memories

Modern processors are far faster than DRAM. To avoid prohibitive wait times, increasingly fast and CPU-proximal caches are used. Most modern processors feature at least three cache levels: L1 (fast and tiny), L2 (larger and slightly slower), and L3 (even larger and slower). Some processors share these caches between multiple cores, while others isolate them. Caches do not work byte by byte but in 64-byte blocks (cache lines), which explains why sequential accesses are faster than random ones.

Multi-core systems introduce additional challenges. Two cores modifying variables located in the same cache line can cause repeated invalidations, slowing execution despite the absence of logical sharing. Protocols like MESI (Modified, Exclusive, Shared, Invalid) maintain cache coherence but do not eliminate the need for synchronization rules in multithreaded programs.

Virtual memory and NUMA

Modern systems use virtual memory: virtual addresses are translated into physical addresses by the memory management unit (MMU) via page tables. To speed up this translation, a dedicated cache, the TLB (Translation Lookaside Buffer), stores recent mappings. Memory pages are typically 4 KB, though larger sizes are sometimes used.

On multi-processor systems or chiplet-based architectures, memory access can be non-uniform (NUMA). A processor accesses local memory faster than that of another node, even if both are in RAM. The operating system attempts to optimize data location to reduce these gaps.

Finally, virtual memory allows not all data to be immediately loaded into RAM. On access to a non-present page, a page fault is generated, and the operating system decides whether to load it from disk, a mapped file, or allocate it. RAM thus serves as a cache for secondary storage, much like L3 cache serves as a cache for RAM.
