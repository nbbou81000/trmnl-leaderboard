A Raspberry Pi That Auto-Repairs Itself When Services Fail

A background script monitors and auto-heals a Raspberry Pi Zero 2 W, eliminating manual intervention.

Read the article on the TRMNL Leaderboard →

A user built a Raspberry Pi Zero 2 W setup to handle home network tasks, running Unbound (DNS resolver), Pi-Hole (ad-blocking), and Docker containers for monitoring tools and a dashboard. Despite its reliability, occasional service or container failures could disrupt operations.

To avoid manual SSH interventions, a background script was created. Launched at startup via Systemd, it periodically checks critical services: Docker, Pi-Hole, Unbound, and Tailscale. If a Docker container is inactive, it restarts it. For Pi-Hole and Unbound, it sends a DNS query to confirm functionality before attempting a restart. Tailscale, deployed outside containers, is also monitored and restarted if needed.

The script includes an external network connectivity check via ping, preventing unnecessary system reboots. Generated logs help identify recurring issues or recreate failed containers. While not foolproof, the script automates basic maintenance tasks and minimizes downtime.
