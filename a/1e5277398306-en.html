A terminal-based SDR monitor written in Rust, now open source

An open-source Rust tool to monitor radio signals in real time via SDR, compatible with multiple hardware setups.

Read the article on the TRMNL Leaderboard →

MusiThang has released sdrtool, a terminal-based monitor for software-defined radio (SDR) hardware, written in Rust. The tool displays a spectrum, a waterfall plot, and a set of measurement instruments within a tmux pane, an SSH session, or a small cyberdeck screen. Key metrics include a Friis noise figure model, bandwidth measured around the carrier instead of the full capture span, and a noise floor reported as a density to prevent shifts with sample rate changes.

Measurement panels automatically mark themselves as [STALE] when the receiver stops. The project has been tested on real hardware: HackRF One, RTL-SDR, and tinySA Ultra ZS405. Other devices with a SoapySDR driver should work, but the backend was built from the API rather than direct hardware testing—only a HackRF setup via SoapyHackRF has been verified.

Additional features in development include decoding RDS from the 57 kHz FM subcarrier and detecting classic Bluetooth piconets via access codes. The software runs on Linux, requires installation via a dedicated script, and needs Rust 1.88 or newer along with a C compiler. Available on GitHub and crates.io, the project is still in early development.
