LabWired: Simulate MCU Firmware Before Testing on Real Hardware

An open-source tool simulates complete microcontroller boards to quickly validate compiled firmware without physical hardware.

Read the article on the TRMNL Leaderboard →

LabWired, an MIT-licensed tool by Andrii Shylenko, enables engineers to test compiled firmware on simulated microcontroller boards. Unlike traditional emulators that only model the CPU, LabWired simulates entire boards, including peripherals like sensors, displays, and bus devices, while capturing UART traffic, register states, and supporting repeatable CI checks.

Supported architectures include Arm Cortex-M (M0+, M3, M4, M7, M33), RISC-V, and Xtensa LX6/LX7 (found in some ESP32 models). The tool models specific boards such as STM32L476, RP2040, nRF52840, and ESP32, providing a faster alternative to physical hardware testing. Developers avoid slow flashing cycles and risks like dead LEDs with no error traces.

LabWired operates primarily as a CLI tool but includes a Browser Playground for interacting with a simulated NUCLEO-L476RG board connected to an ultrasonic sensor, a Nokia display, and a logic analyzer. A real-world example demonstrates a Unity firmware tested on a virtual nRF52840 using the command pio test --without-uploading -e nrf52840_dkon, completing in 1.18 seconds compared to minutes on physical hardware. Over 200 board configurations are available in examples, with a validation matrix listing supported peripherals.

LabWired offers two usage modes: standalone integration via its open-source Rust code or a paid cloud service using LabWired AI Tokens. The core simulator, including CLI and tracing tools, is open source, while the user interface and hosted features belong to a separate package. A pricing page outlines available options.
