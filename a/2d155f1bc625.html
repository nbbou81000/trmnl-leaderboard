LabWired : simuler le firmware d’un microcontrôleur avant de le tester sur matériel réel

Un outil open source simule des cartes microcontrôleurs complètes pour valider rapidement le firmware compilé sans matériel physique.

Lire l'article sur le Palmarès TRMNL →

LabWired, développé par Andrii Shylenko sous licence MIT, propose une solution pour tester des firmwares compilés sur des microcontrôleurs simulés. Contrairement à un émulateur classique qui ne modélise que le processeur, LabWired simule l’intégralité d’une carte, incluant le CPU, les périphériques (capteurs, écrans, bus) et leurs interactions. L’outil capture les échanges UART, les états des registres, et permet des vérifications reproductibles dans des environnements d’intégration continue (CI).

Les architectures supportées couvrent les cœurs Arm Cortex-M (M0+, M3, M4, M7, M33), RISC-V, ainsi que les Xtensa LX6 et LX7 (présents sur certains ESP32). LabWired se distingue par sa capacité à modéliser des cartes spécifiques comme le STM32L476, le RP2040, le nRF52840 ou l’ESP32, offrant une alternative rapide aux tests sur matériel réel. Les développeurs évitent ainsi les cycles lents de flashage et les risques de blocage (LED éteinte sans trace d’erreur).

L’outil s’utilise principalement en ligne de commande, mais inclut aussi un Browser Playground pour interagir avec une carte simulée NUCLEO-L476RG connectée à un capteur ultrasonique, un écran Nokia et un analyseur logique. Un exemple concret montre un firmware Unity testé sur un nRF52840 virtuel via la commande pio test --without-uploading -e nrf52840_dkon, exécuté en 1,18 seconde contre plusieurs minutes sur matériel physique. Plus de 200 configurations de cartes sont disponibles dans les exemples, avec une matrice de validation listant les périphériques supportés.

LabWired propose deux modes d’utilisation : une intégration autonome via son code Rust open source ou un service cloud payant utilisant des LabWired AI Tokens. Le cœur du simulateur, incluant le CLI et les outils de traçage, est open source, tandis que l’interface utilisateur et les fonctionnalités hébergées relèvent d’un package séparé. Une page de tarification détaille les options disponibles.
