Claude uncovers 3 hidden issues in a Proxmox homelab

A user tasked an AI with analyzing his homelab and uncovered critical issues overlooked for months.

A homelab administrator tasked the AI Claude with auditing two Proxmox servers without altering their settings. The AI identified three major issues that had gone unnoticed despite regular checks.

Incomplete backups

Nightly Proxmox backups appeared successful, showing an "OK" status for each service. However, the AI found that critical applications like Immich (photo and video storage) were no longer included. The owner had manually deselected some services to save space but forgot to add new ones installed later. The proposed fix is to enable automatic backup of all services by default, then manually exclude unnecessary ones.

IPv6 connectivity failure

A silent IPv6 address change by the ISP made a DNS service (Pi-hole) unreachable for some applications. While most services used IPv4 or another DNS server, certain plugins relying on IPv6 had been failing silently for weeks. Local tasks like streaming via Jellyfin worked normally, masking the issue.

An unupdated server

One Proxmox server, installed on an old Dell OptiPlex PC, had not received any updates since setup. The owner disabled the paid update source without enabling the free one for homelabs. As a result, the server remained stuck on version 9.1.1, while patches and version 9.2 were available. Debian updates still appeared in the interface, creating a false impression of normal operation.

These seemingly invisible issues highlight the importance of regularly checking service configurations and update sources, even when everything appears functional.
