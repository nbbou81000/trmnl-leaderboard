A $2 Pi-hole-Style DNS Ad-Blocker on ESP32-C3 Without PSRAM

A lightweight DNS blocker runs on a $2 ESP32-C3 without PSRAM by storing domains as binary hashes in flash memory.

This open-source project turns a $2 ESP32-C3 microcontroller into a Pi-hole-style DNS ad-blocker without requiring PSRAM. The key innovation is storing domains as 40-bit binary hashes (using the FNV-1a algorithm) in flash memory instead of strings in RAM. This approach packs over 537,000 domains into roughly 0.7 MB of flash, with a lookup time of about 10 ms and a RAM footprint of just 50 KB.

The system acts as a DNS sinkhole: requests to blocked domains receive a 0.0.0.0 response, while others are forwarded to an upstream DNS server. The project includes a web dashboard for managing blocklists, updating firmware, or configuring the network. Default blocklists combine entries from StevenBlack and Hagezi Light, covering around 100,000 domains, with support for custom rules via hosts files or basic AdGuard rules.

The project works with most ESP32-C3 boards (tested on a C3 SuperMini) and even classic ESP32 models like DevKit or WROOM, provided they have 4 MB of flash. Initial setup is done via a temporary Wi-Fi access point or directly through the dashboard once connected to the network. Subsequent firmware and blocklist updates are performed wirelessly. A 3D-printable enclosure is available, with tips to preserve Wi-Fi signal quality (avoiding obstructions near the PCB antenna).

The project is released under the MIT license and requires the PlatformIO tool for compilation and flashing. A simplified browser-based installer is in development. Automatic blocklist updates are available weekly via a stable URL hosted on GitHub.

Limitations include a trade-off in partition size for OTA firmware updates, reducing available space for blocklists to about 1.3 MB (~250,000 domains). Sensitive dashboard features (such as adding domains or updates) are protected by HTTP Basic authentication.
