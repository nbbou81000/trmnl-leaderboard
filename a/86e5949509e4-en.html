Smart TVs and Pi-hole: Why Ads Still Slip Through (and How to Fix It)

Smart TVs and other devices often bypass Pi-hole. Here’s why and how to plug the leaks.

A Pi-hole blocks thousands of DNS queries weekly, yet smart TVs and other devices still display ads. The issue? These devices deliberately bypass the local DNS server to connect directly to manufacturer servers.

Why Pi-hole sometimes fails

A Pi-hole works by intercepting DNS requests before they reach an external server. However, some devices use hard-coded DNS (e.g., 8.8.8.8) or encrypted protocols like DNS over HTTPS (DoH) or DNS over TLS (DoT). These methods bypass the Pi-hole because they encrypt requests or use non-standard ports (853 for DoT, 443 for DoH), preventing interception.

Smart TVs, connected speakers, and even some smart refrigerators are often configured to use these alternatives, making the Pi-hole ineffective against their built-in ads.

Solutions to force traffic through Pi-hole

Several methods can limit these workarounds:

  • Configure the router to distribute only the Pi-hole’s address as DNS for both IPv4 and IPv6 protocols.
  • Redirect DNS traffic via a NAT rule on the router, forcing unencrypted requests (port 53) through the Pi-hole.
  • Block port 853 to prevent DoT usage, unless the Pi-hole is configured to handle DoT downstream.
  • Block DoH server IP addresses using a blacklist on the router, forcing devices to use the local DNS or be blocked.

These settings require a compatible router, such as those running third-party firmware (OpenWrt) or advanced software solutions (OPNsense, pfSense). An alternative is to build a DIY router with two Ethernet ports and one of these software options.

Without these options, some devices must be disconnected from the network or manually configured to use the Pi-hole.
