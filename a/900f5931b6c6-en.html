How to Detect and Remove a Hidden Cryptominer in Your Homelab

A compromised homelab may host a hidden cryptominer without obvious signs. Here’s how to detect and remove it.

A cryptominer running in a homelab doesn’t always max out the CPU. Some variants operate quietly, throttling their resource usage to avoid detection. In one case, the author only noticed an issue after trying to use a compromised NAS, observing unusual slowdowns. In another, a rack-mount server’s fans spun at 100 % due to the miner’s high load.

To catch these intrusions early, monitoring tools like Grafana and Prometheus are essential. They track system performance over time, making it easier to spot sudden, unexplained spikes in CPU usage—especially during idle periods. A smart plug measuring power consumption can also reveal unexpected energy draws when no activity is expected.

Malicious processes often disguise themselves with generic names like kworker or random strings, and run from unusual directories such as /tmp or /dev/shm. In containerized environments, check for unknown Docker containers using docker ps -a and analyze their resource usage with docker stats. Cryptominers may also hide in systemd services, cron jobs, or by adding SSH keys for persistent access.

Network traffic is the cryptominer’s Achilles’ heel, as it must communicate with external mining pools. The ss -tunp command helps identify suspicious outbound connections. Tools like Pi-hole or AdGuard Home can block these communications by filtering mining pool domains. However, a malicious Docker container might bypass these protections by overriding DNS settings.
