Swapping TrueNAS for Debian and Cockpit on an 8GB Home NAS: 2.5GB of RAM Reclaimed

A user replaces TrueNAS with Debian 13 and Cockpit on an 8GB home NAS, freeing 2.5GB of RAM and streamlining management.

A user replaced TrueNAS 25.10, a dedicated NAS operating system, with Debian 13 and Cockpit, a web-based Linux server dashboard, on an 8GB home server. After three weeks, they reported reclaiming 2.5GB of RAM, reducing usage from 3.2GB to just 640MB.

TrueNAS, while based on Debian, is optimized for appliances and consumes significant resources at startup. Its web interface, integrated apps, and ZFS filesystem share the same memory pool, leaving little room for read caching. The user noted that TrueNAS requires at least 8GB of RAM as a baseline, a high threshold amid ongoing RAM shortages. Additionally, installing extra packages is blocked to prevent conflicts, limiting customization.

Switching to Debian 13 freed up memory while maintaining the same functionality. ZFS, available in Debian's contrib repositories, was installed via trixie-backports with version 2.4.3, newer than TrueNAS's 2.3.4. The ZFS pool was imported without data loss, and Cockpit was set up to manage Samba, NFS, iSCSI, and S3 shares using dedicated plugins. Cockpit's memory footprint remains minimal thanks to socket activation—it only runs when a user accesses the dashboard.

However, some advanced TrueNAS features, like automatic Time Machine backups for macOS or disk health alerts, aren’t enabled by default in Debian. Manual configuration is required, which can be time-consuming. Despite this, the user found Debian with Cockpit offers greater flexibility for modest hardware while freeing up enough resources to run containers (Podman) and a virtual machine (Home Assistant).
