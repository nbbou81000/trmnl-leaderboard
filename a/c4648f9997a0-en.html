DeviceTree: Understanding Hardware Description Files

DeviceTree files reveal the secrets of boards like the upcoming Raspberry Pi Zero 3W.

The Raspberry Pi project has leaked details about the upcoming Pi Zero 3W through a DeviceTree file, a technical document describing the board’s hardware. The file reveals the use of the BCM2711 processor (found in the Pi 4), a potential PCIe port, an onboard power button, an extra power LED, and an eMMC storage option. Observers speculate the board may feature a dual-sided design and finally adopt a USB-C connector.

DeviceTree is a hardware description language used by Linux kernels and other operating systems to configure drivers and interfaces. These files, compiled into binary format (.dtb), are ubiquitous in smartphones, routers, ARM laptops, and single-board computers (SBCs). Their structure resembles HTML but lacks Turing completeness. They consist of source files (.dts, .dtsi) and compiled files (.dtb, .dtbo).

Three types of DeviceTree files exist: include files (.dtsi) containing basic technical definitions, base files describing the entire board, and overlays that add or modify features. Overlays are particularly useful for enabling peripherals or adjusting settings without altering the base file. For instance, an overlay can activate an LED connected to a GPIO, disable Wi-Fi, or configure an I2C touchscreen. Their syntax is straightforward, often based on existing examples to modify.

Tools like device-tree-compiler (available via apt) make it easy to compile or decompile these files. On Raspberry Pi, overlays can be loaded dynamically via config.txt, while other platforms integrate them through uBoot. Conventions vary by architecture: GPIO pointers are named &gpio on Raspberry Pi but &pio or &gpio1 on others. Comments follow C-style syntax (// or /* */), while metadata like #size-cells is critical for interpreting properties such as <reg>.

Numerous examples are available in official Linux, Radxa, Armbian repositories, or on GitHub, where thousands of .dts files are shared. These resources enable creating or modifying overlays even without prior experience, by drawing inspiration from existing projects.
