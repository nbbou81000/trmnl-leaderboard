DeviceTree : comprendre les fichiers de description matérielle

Les fichiers DeviceTree révèlent les secrets des cartes comme le futur Raspberry Pi Zero 3W.

Lire l'article sur le Palmarès TRMNL →

Le projet Raspberry Pi a dévoilé des indices sur le futur Pi Zero 3W via un fichier DeviceTree, un document technique décrivant le matériel. Ce fichier révèle l’utilisation du processeur BCM2711 (celui du Pi 4), la présence d’un port PCIe potentiellement accessible, un bouton d’alimentation intégré, une LED d’alimentation supplémentaire et une option de stockage eMMC. Selon les observateurs, la carte pourrait adopter une conception double face et enfin migrer vers un connecteur USB-C.

DeviceTree est un langage de description matérielle utilisé par les noyaux Linux et autres systèmes d’exploitation pour configurer les pilotes et interfaces d’une carte. Ces fichiers, compilés en binaire (.dtb), sont omniprésents : smartphones, routeurs, ordinateurs portables ARM ou cartes monocarte (SBC) en dépendent. Leur structure rappelle celle du HTML, mais sans être Turing-complet. Ils se composent de fichiers sources (.dts, .dtsi) et de fichiers compilés (.dtb, .dtbo).

Trois types de fichiers DeviceTree existent : les fichiers d’inclusion (.dtsi) contenant des définitions techniques basiques, les fichiers de base décrivant la carte dans son ensemble, et les overlays qui ajoutent ou modifient des fonctionnalités. Ces derniers sont particulièrement utiles pour activer des périphériques ou modifier des paramètres sans altérer le fichier de base. Par exemple, un overlay peut activer une LED connectée à un GPIO, désactiver le Wi-Fi ou configurer un écran tactile I2C. Leur syntaxe est accessible, souvent basée sur des exemples existants à adapter.

Pour manipuler ces fichiers, des outils comme device-tree-compiler (disponible via apt) permettent de les compiler ou décompiler facilement. Les overlays Raspberry Pi, par exemple, peuvent être chargés dynamiquement via config.txt, tandis que sur d’autres plateformes, ils s’intègrent via uBoot. Les conventions varient selon les architectures : les pointeurs GPIO s’appellent &gpio sur Raspberry Pi, mais &pio ou &gpio1 sur d’autres cartes. Les commentaires suivent la syntaxe C (// ou /* */), tandis que des métadonnées comme #size-cells sont essentielles pour interpréter les propriétés comme <reg>.

De nombreux exemples sont disponibles dans les dépôts officiels Linux, Radxa, Armbian ou sur GitHub, où des milliers de fichiers .dts sont partagés. Ces ressources permettent de créer ou modifier des overlays même sans expérience préalable, en s’inspirant de projets existants.
