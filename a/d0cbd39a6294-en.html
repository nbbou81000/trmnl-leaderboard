A Local LLM Controls My Home Assistant… and Sometimes Goes Off the Rails

A user integrates a local language model with Home Assistant to automate home tasks, but comprehension errors force them to add safeguards.

Read the article on the TRMNL Leaderboard →

A journalist connected a local language model (LLM) to their Home Assistant setup to interpret complex voice commands alongside native voice commands. The model, such as Qwen3 1.7B, runs on a separate machine (a Mac in this case) and is accessible over the local network via Ollama. Home Assistant, installed on another machine, uses the Ollama integration to send requests to the LLM, which then selects the appropriate tools (entities or scripts) to fulfill the request.

The benefit is more natural command interpretation, but comprehension errors remain frequent. The model may confuse similar actions (turning off lamps instead of lights), trigger unsolicited routines (like a "Good night" scenario in response to a question about a light’s status), or apply commands to unintended areas. Some requests even result in the display of tool call code instead of executing the action.

To mitigate these risks, the author restricted the LLM’s access to a limited number of entities (fewer than 25, as recommended by Home Assistant) and favored predefined scripts for multi-step actions. Exposed tools are also configured to reject parameters outside certain limits (e.g., a thermostat’s temperature range). These safeguards reduce errors but do not eliminate them entirely, as the model can still misinterpret instructions despite technical restrictions.
