A 744-Billion-Parameter Model Runs on 16 GB RAM Using Arduino

An engineer runs a massive language model on an Arduino with just 16 GB RAM, using a clever software trick.

Read the article on the TRMNL Leaderboard →

Engineer Jim Bruges has shown that it’s possible to run massive language models locally on modest hardware by bypassing RAM limitations. His setup uses an Arduino VENTUNO Q single-board computer, featuring a quad-core Cortex-A78C processor, paired with a 1 TB NVMe SSD to store model weights. The software, Colibri, an open-source inference engine, leverages the mixture-of-experts architecture of the Qwen3.6-35B-A3B and GLM-5.3 models (744 billion parameters).

Unlike traditional methods that load all parameters into RAM, Colibri only loads the required experts into memory for each token generation. The rest remain stored on the SSD and are loaded on demand, with a cache for recently used experts. This means the system doesn’t need enough RAM to hold the entire model at once. The quantized Qwen model takes up about 23 GB of storage, while GLM requires a massive 419 GB. Inference runs under Ubuntu 24.04 without using the GPU or NPU.

Performance is understandably slow: with a 96-slot expert cache, Qwen generates around 0.74 tokens per second (0.774 with CPU frequency tuning), while GLM manages just 0.03 tokens per second. In one test, GLM took seven minutes to respond with "Earth, Mars, Venus" when asked for three planets. While not practical for real-time applications, this approach offers an alternative for latency-tolerant use cases or experiments with enormous models on low-end hardware.
