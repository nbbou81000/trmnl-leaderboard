Cloudflare Quick Tunnels : exposer un serveur local en ligne avec contrôle d'accès

Cloudflare propose des tunnels temporaires pour partager un serveur local via une URL aléatoire, avec une option pour restreindre l'accès par e-mail.

Cloudflare Quick Tunnels permet d’exposer un serveur local sur Internet sans configuration complexe : une commande cloudflared tunnel --url génère une URL aléatoire en trycloudflare.com, sans besoin de compte, de domaine ou d’ouverture de port. Idéal pour des tests ou des démonstrations rapides, ce service offre une solution temporaire et sans engagement.

Installation et utilisation

L’outil cloudflared, client open source de Cloudflare, s’installe facilement selon la plateforme. Sous macOS avec Homebrew (brew install cloudflared), sous Debian/Ubuntu via un dépôt officiel mis à jour récemment, ou sous Windows via un MSI, un exécutable ou Winget (winget install Cloudflare.cloudflared). La version 2026.9.3 ou ultérieure est requise pour bénéficier des options d’authentification.

Une fois installé, lancez votre serveur local (par exemple sur le port 8080) et exécutez cloudflared tunnel --url http://localhost:8080. Cloudflare génère une URL aléatoire du type quelque-chose-truc-bidule.trycloudflare.com, accessible depuis n’importe quel appareil connecté à Internet. Pour arrêter le tunnel, un simple Ctrl+C suffit.

Restriction d’accès par e-mail

Une nouveauté récente permet de limiter l’accès au tunnel à des adresses e-mail spécifiques via l’option --allowed-mail. Chaque invité reçoit un code à usage unique envoyé par Cloudflare Access pour s’authentifier. Les adresses autorisées ne sont pas visibles dans la configuration, évitant toute fuite de données personnelles. Plusieurs e-mails peuvent être ajoutés, séparés par des virgules, ou un domaine entier avec un joker (--allowed-mail '*@example.com').

Cette fonctionnalité est particulièrement utile pour partager un projet en cours avec une équipe restreinte ou pour éviter qu’un agent IA ne publie accidentellement un tunnel public. Cloudflare recommande également l’utilisation d’un hook PreToolUse pour bloquer les commandes sans restriction d’accès.

À noter : Quick Tunnels est conçu pour des usages temporaires et non pour un déploiement en production. Cloudflare ne garantit pas la disponibilité du service, et chaque tunnel est limité à 200 requêtes simultanées. Les Server-Sent Events (SSE) ne sont pas supportés. Pour un usage professionnel, il est préférable de créer un tunnel nommé via un compte Cloudflare et un domaine personnalisé.
