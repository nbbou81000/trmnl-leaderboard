Arduino simplifies ROS 2 integration for microcontrollers

An open-source library merges Linux and real-time environments in ROS 2.

Read the article on the TRMNL Leaderboard →

Robotics projects using ROS 2 often rely on a classic split: a Linux computer handles navigation and planning, while a real-time microcontroller manages I/O operations. This setup usually requires complex communication protocols or heavy middleware to bridge the two layers.

To simplify this integration, Arduino unveiled at ROSCon Global 2026 and ROSCon Italy an open-source solution: the Arduino_RouterBridge_ROS library. Designed to work with the VENTUNO Q board—which combines a Linux-capable processor and a real-time microcontroller—it enables executing functions between both environments as if they were unified.

The core of the solution is Arduino_RouterBridge, an RPC (Remote Procedure Call) protocol based on MsgPackRPC. It allows calling functions between the Linux side (Python) and the microcontroller side (Zephyr-based sketch) using two simple methods: Bridge.provide() to expose a function, and Bridge.call() to invoke it. The new library extends this mechanism to ROS 2, enabling the instantiation of nodes, publishers, subscribers, services, and actions directly from the microcontroller firmware.

This approach provides a native C++ interface compatible with ROS 2 standards (rclcpp), while remaining independent of the middleware (RMW) used on Linux. Developers can publish sensor data like IMU telemetry to a /imu/data topic or receive velocity commands on /cmd_vel without setting up intermediate nodes. Official guides detail its use on the VENTUNO Q board, including examples to start a ROS 2 project or build a first robotic application.
